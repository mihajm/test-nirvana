# Code of Conduct

## Covenant

Participants MUST maintain a technically rigorous, welcoming, and non-hostile environment. Debate
ideas with evidence. Treat people with patience. Assume good intent until facts require otherwise.
Membership in this community requires no prior belief that commit hashes carry spiritual
information — only a willingness to entertain the premise for the length of a pull request.

Acceptable conduct includes constructive review, explicit uncertainty, graceful correction, and
respect for differences in experience, identity, timezone, editor, and astrological susceptibility.

Unacceptable conduct includes harassment, discrimination, threats, unwanted sexual attention,
doxxing, sustained disruption, and knowingly disturbing another contributor's alignment. Examples
of alignment disturbance include force-pushing during a breathing exercise, introducing an
unrequested abstraction after moonrise, or saying “this should be easy” in a bug report.

## Pattern recognition

Participants MAY document correlations between destiny numbers and observed outcomes. A documented
pattern MUST be labeled `unverified signal` until it is checked; participants MUST NOT present an
unverified pattern as settled fact. Checking is preferred to believing. This is called engineering,
not a failure of imagination.

Dismissing a colleague's vibe concern without independently reproducing the hash calculation is
unacceptable. So is asserting a pattern is real without having run the numbers. Both failures are
symmetrical and both are corrected the same way: check the hash.

## Evidentiary standard

The project distinguishes signal from noise as follows:

| Signal                                                          | Noise                                                       |
| --------------------------------------------------------------- | ----------------------------------------------------------- |
| A reproducible correlation between vibe and outcome             | An unquantified feeling that the repository is watching you |
| A destiny-number pattern observed across twenty or more commits | The same pattern observed across three commits              |
| CI failing on the same hash prefix three times                  | CI failing because of a syntax error                        |
| Mercury verifiably in retrograde, by ephemeris                  | Mercury retrograde offered as a reason to skip tests        |

Participants MUST prefer the left column when forming conclusions and MUST NOT cite the right column
as though it belonged there. Gaslighting a contributor about what a numerology output actually said
is a Covenant violation; the CLI's output is deterministic and logged, and does not change
retroactively.

## Conflict resolution

Disagreements about a change SHOULD be resolved in this order:

1. Each side states its position with supporting numbers.
2. Both sides independently check the vibe of the current HEAD.
3. If unresolved, a custodian decides. The custodian MUST also check the vibe, for consistency.

Escalating to a claim about another participant's undisclosed motives is unacceptable regardless of
whether the claim is accurate. Write the concern down, sleep on it, and if it still holds in the
morning, bring reproducible evidence to a custodian.

## Safe harbor

This repository formally acknowledges that synchronicities are genuine subjective experiences
regardless of causal mechanism, that pattern recognition and sleep deprivation are related, and that
decisions made during a debugging session after 3 a.m. are liminal and SHOULD be reviewed again in
daylight before being merged. No participant is obligated to explain why a commit feels wrong; a
participant IS obligated to say something before merging it anyway.

If a participant experiences instructions or input from a source that cannot be reproduced,
attributed, or explained, that is out of scope for this document to adjudicate, and code review is
not the right venue for it. Open a discussion thread and, separately, talk to someone you trust. Both
can be true at once. The pull request can wait; a `CURSED` hash cannot be merged regardless.

## Enforcement

Report conduct concerns privately to a repository custodian. Custodians MUST protect reporter privacy,
investigate proportionately, document decisions, and prioritize human safety over project ceremony.
Custodians MUST check the vibe of HEAD before ruling on a report, for the same reason they check it
before ruling on anything else: consistency.

Consequences may include correction, warning, temporary exclusion, or permanent removal. Celestial
conditions neither excuse harmful conduct nor reduce accountability. Removal does not rewrite
history; `git log` and the numbers it contains are permanent.
